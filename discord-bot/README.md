# Experimental ItemShare Discord client

Run from this directory with Node 20 or newer. `discord.js` is pinned to 14.19.3 (its published engine requirement is Node >=18); this standalone package requires Node >=20. Install with `npm ci`, copy `.env.example` to `.env`, configure the five settings, then run `npm run deploy-commands` and `npm start`. Deployment replaces this application's commands only in the configured development guild. Do not use a production application/token for the experiment. `npm test` uses fake interactions and an injected HTTP transport; no credentials are needed.

`ITEMSHARE_API_URL` is the server origin, without `/api/discord/v1`. HTTPS is required outside localhost. Dedicated API bearer credentials belong only in `.env`; never share them with Discord members. Dotenv reads `.env` from the working directory. No message-content intent is used. The bot requests only the Guilds gateway intent and sends ephemeral interaction responses; it never posts channel notifications.

`/items browse`, `/items search name`, and `/items categories` provide private navigation. Browse result buttons open full item details and explicit confirmation. `/items request item [quantity]` accepts `inventory:ID` or `offer:ID` and opens the same confirmation. Change quantity opens a modal, followed by a fresh confirmation. Cancel submits nothing. An account must be selected first using `/items account eso:@Account`; `/items account` displays selection and associations. Provisional recipients remain subject to officer review. `/items requests` lists your requests. `/items review [action] [user] [eso]` delegates officer authorization and association review to the API. `/items help` summarizes commands.

Controls belong to the member who created them and expire after ten minutes or a process restart. At most 1,000 sessions are retained; oldest sessions are evicted when full. There is no persistent client state. Requests are never automatically retried, including after a network timeout; check `/items requests` before making a new confirmation. A used or uncertain confirmation cannot submit again. The API remains authoritative for guild/role authorization, references, scope, stock, recipients, quantity limits and idempotency.

No live command registration, Discord login or real request has been performed during development. Test guild visual review and actual interaction round trips remain required before use. Remove the application's guild installation and stop its process to retire the experiment; backend disabling/removal is documented in the repository guide.
